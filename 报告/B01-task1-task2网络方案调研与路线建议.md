# B01 task1/task2 网络方案调研与路线建议

> 调研目的：基于当前已获得的 B01 初赛 stage1 数据，检索论文、官方模型资料和开源项目，筛选能够在 B01 约束下落地的 task1（航迹理解）与 task2（跨模态检索）方案，为后续路线选择提供事实依据。
>
> 本报告不把论文中的实验结果直接等同于 B01 的可得分结果。每种方法都单独标出适用依据、需要改造的部分和主要风险。

## 1. 结论摘要

建议采用“模型负责语义解析和语义判别，确定性模块负责可验证的数值、几何、时间计算”的混合路线。

- task1 航迹分段：先做轨迹清洗和变化点候选检测，再用本地模型或轻量时序模型判定阶段语义和选项。研究上，语义轨迹分段通常先检测运动模式变化，再进行语义标注；SEMANTIC-SEG 明确采用了这一两阶段思路，[SEMANTIC-SEG](https://doi.org/10.1080/13658816.2020.1798966)。
- task1 区域理解：多边形进入、离开、停留和进入顺序应由几何事件引擎计算，模型只负责理解题意、选择需要的统计口径和最终语义判别。Shapely 官方文档给出了 contains、within、边界行为以及重复几何运算的 prepared geometry 机制，[Shapely User Manual](https://shapely.readthedocs.io/en/stable/manual.html)。
- task2 检索：先将中文查询解析为结构化查询 IR，再用时间、高度、速度、区域和否定条件做硬过滤，最后对候选航迹做稠密/稀疏召回与交叉编码器重排。文本检索中“bi-encoder 初召回 + cross-encoder 重排”是成熟的合作式结构，[Retrieve Fast, Rerank Smart](https://aclanthology.org/2022.tacl-1.29/)。
- 本地模型候选：Qwen3-1.7B/4B 或当前环境更易直接使用的 Qwen2.5-3B，均为国内开放权重，可用于查询解析和选项判别。[Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B)、[Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)、[Qwen2.5-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct)
- 检索模型候选：BGE-M3 支持稠密、稀疏和多向量检索；BGE-reranker-v2-m3 是用于候选重排序的 cross-encoder。[BGE-M3](https://arxiv.org/abs/2402.03216)、[BGE-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)
- 最稳妥的首版：只用一个符合参数上限的本地主模型，加确定性计算和普通文本/结构化索引，先建立可复现基线；确认赛方对“专用模型”计数口径后，再加入 BGE-M3 或 reranker。

## 2. 当前数据决定了问题类型

### 2.1 官方任务形态

官方 README 表明 stage1 包含：

- task1 分段理解：50 条四选一；
- task1 区域理解：50 条四选一；
- task2 检索问题：50 条，top_k 为 10—15；
- task2 航迹库：约 2000 条航迹、483657 个点。

本地数据统计结果：

| 数据 | 数量或范围 | 对路线的影响 |
|---|---:|---|
| 分段题 | 50 条 | 适合做开发集和错误分析，不适合直接训练大模型 |
| 区域题 | 50 条 | 需要严格实现多边形事件语义 |
| 检索题 | 50 条 | 可覆盖查询表达，但数量不足以训练大规模检索器 |
| 航迹库 | 2000 条 / 483657 点 | 可离线建立完整轨迹索引，首版不需要向量数据库 |
| 航迹长度 | 25—1101 点，平均约 241.8 点 | 必须先做轨迹摘要和分段，不能把所有点直接塞入模型 |
| task1 分段输入点数 | 58—723 点，平均约 313.1 点 | 数值特征和局部窗口比原始长文本更合适 |
| task1 区域输入点数 | 151—861 点，平均约 465.6 点 | 几何事件引擎可以显著降低模型负担 |

检索题中出现的条件：

- 时间条件：40/50；
- 区域条件：40/50；
- “先……随后……”等顺序词：30/50；
- 高度：22/50；
- 速度：19/50；
- 否定条件：7/50；
- 加速：24/50；
- 盘旋：26/50；
- 绕飞：26/50。

这说明 task2 不是普通的相似文本检索，而是带有数值、空间、否定和顺序约束的时空检索。task1 分段题同样同时出现高度、速度、巡航、盘旋、绕飞、直线和跑道等组合语义。

### 2.2 对模型设计的直接约束

1. 时间语义必须分层处理：task1 点位时间是相对起点的秒数，选项可能使用起始 UTC 加相对时间后的绝对时刻；task2 CSV 使用绝对 UTC 时间。
2. 轨迹库先排序再计算：官方 README 已提示同一航迹行不保证按时间排序，并要求处理重复点和异常点。
3. 区域题不能只用点是否在多边形内：还要识别跨边界的进入/离开、起点已在区内的特殊语义、重复进入、进入顺序和停留时长。
4. task2 的否定和顺序不能只靠关键词匹配：例如“满足 A，且不满足经过 E，先盘旋绕飞，随后加速”需要结构化解析和按时间验证。
5. stage1 规模不代表最终规模：stage1 应作为本地开发集和压力样例，不能假定正式测试集只包含 50 条问题。

## 3. B01 约束下的合规边界

根据本地赛题资料，主语义判断必须由符合要求的本地开放权重模型完成；确定性模块可用于数据解析、时间换算、几何运算、索引和格式校验。报告中的路线因此分成三层：

| 层 | 可以做什么 | 不能做什么 |
|---|---|---|
| 数据与工具层 | 排序、去重、坐标换算、速度/航向/曲率计算、点面关系、时间插值、候选过滤、输出校验 | 用固定规则直接替代题目的主要语义判定 |
| 本地模型层 | 从中文题干抽取结构化意图、识别行为和阶段语义、处理表达变体、在候选选项中作语义判别 | 调用闭源在线大模型或把测试样例答案写入映射表 |
| 检索层 | 结构化索引、稠密/稀疏召回、候选重排 | 用不受参数约束的外部模型作为最终答案生成器 |

### 3.1 模型数量和参数风险

B01 资料对专用模型数量和基础模型参数量有约束。BGE-M3、BGE-reranker 和 Qwen 同时使用时，是否把检索编码器和 reranker 计入“专用模型”需要向赛事方确认。

建议保留两种配置：

- 保守配置：一个 Qwen2.5-3B 或 Qwen3-4B 作为唯一主要模型；几何、时间和索引均为非学习工具。
- 增强配置：一个 Qwen 负责查询解析/选项判别，BGE-M3 和 BGE-reranker 负责 task2 检索；只有在赛方确认计数和参数口径后启用。

当前 proj/requirements.txt 固定了 transformers==4.41.2。Qwen3-4B 官方模型卡要求较新的 Transformers 版本（模型卡注明需使用不低于 4.51.0 的版本），因此当前环境与 Qwen3 直接加载存在依赖不匹配。若不先调整环境，Qwen2.5-3B 是更稳妥的实验起点；若后续选 Qwen3，应单独更新并锁定兼容依赖。

## 4. task1：航迹分段理解的研究方案

### 4.1 研究证据

#### A. 变化点检测 + 语义标注

SEMANTIC-SEG 将 GPS 轨迹分成运动条件相对一致的片段，再使用本体和时空概率模型进行语义丰富。论文报告其变化点检测在三个数据集上优于四个基线。[SEMANTIC-SEG](https://doi.org/10.1080/13658816.2020.1798966)

对 B01 的可借鉴点：

- 先识别高度、速度、航向或空间形态发生明显变化的位置；
- 再对候选片段做“巡航、直线、盘旋、绕飞、加速”等语义判断；
- 分段点和阶段顺序可以作为模型输入，避免模型阅读数百个原始点。

需要改造的地方：

- 论文中的本体和规则是其研究方案的一部分，不能直接作为 B01 的最终语义回答器；
- B01 的选项表达需要由本地模型理解，确定性变化点检测只能提供证据和候选边界。

#### B. 无标签航迹表征学习

ATSCC 针对飞机航迹提出基于可分段轨迹特征的自监督对比编码，目标是减少对预定义机场配置、飞行程序和人工标签的依赖，并适配不完整轨迹。[ATSCC](https://doi.org/10.1109/OJITS.2025.3574746)

TrajCL 使用四种轨迹增强和双特征注意力学习轨迹相似性，兼顾空间与结构模式，并支持少量监督微调。[TrajCL](https://arxiv.org/abs/2210.05155)；官方代码：[TrajCL GitHub](https://github.com/changyanchuan/TrajCL)

TrajRCL 使用重构、掩码和对比损失学习空间—时间轨迹表示，并以 Transformer 编码器—解码器提高相似性检索和 kNN 效果。[TrajRCL](https://www.sciencedirect.com/science/article/pii/S0167739X23001443)

对 B01 的可借鉴点：

- stage1 没有公开训练答案，全部 2000 条航迹可以先做无标签预训练；
- 自监督表征可作为分段模型和 task2 召回器的特征；
- 增强时要保持真实的时间顺序和空间几何，不能使用会改变题目语义的随机扰动。

### 4.2 推荐的 task1 处理链

#### 第一步：轨迹标准化

对每条 task1 轨迹：

1. 按相对时间排序；
2. 去除完全重复时间点或重复坐标点；
3. 记录时间间隔、空间距离、高度差、速度差和航向变化；
4. 对经度跨 180 度、航向 0/360 度跳变、异常大速度变化做环绕和异常处理；
5. 将相对时间转换为 UTC 时间，但保留原相对时间作为题目统计主轴。

计算的基础特征：

- 水平位移、3D 位移和单位时间速度；
- 航向角的环绕差分；
- 转弯率、局部曲率、横向偏移；
- 高度变化率、加速度和减速度；
- 局部窗口的直线拟合误差、圆形/椭圆形拟合误差；
- 点位是否进入给定区域。

#### 第二步：候选分段

优先比较三种无标签或弱监督方法：

1. 滑动窗口统计量的变化点检测；
2. 基于速度、高度、航向和曲率的多变量变化点检测；
3. ATSCC/TrajCL 风格的自监督表征后，再在表征序列上做变化点检测。

第一版不应直接训练复杂端到端网络。先把候选边界、段长和误切分情况可视化，确认“直线—盘旋—加速”等模式在数据中能被特征区分。

#### 第三步：语义判别

将每个候选片段压缩为结构化摘要，例如：

- 起止相对时间和绝对时间；
- 平均/分位数速度；
- 高度起止值和变化方向；
- 航向变化总量；
- 转弯率和曲率分布；
- 直线拟合误差；
- 盘旋/绕飞候选分数；
- 与区域的关系。

再由本地模型完成：

- 阶段语义识别；
- 阶段顺序理解；
- 四个选项的语义匹配；
- 输出单个选项字母。

可采用 Qwen2.5-3B 或 Qwen3-1.7B/4B 的结构化输出提示。模型输入是“题干 + 片段摘要 + 必要的少量证据”，而不是数百个 JSON 点位。

### 4.3 task1 分段的训练数据策略

stage1 只有 50 道题，不能用来训练大模型。建议构造三类训练样本：

1. 程序生成轨迹：生成直线、匀速巡航、爬升、下降、加速、减速、定半径盘旋、绕飞和组合序列，并加入采样不均匀、缺点和测量噪声。
2. 弱标注真实轨迹：用几何和时序特征生成候选标签，再人工抽查边界和语义。
3. 文本扰动样本：为同一阶段序列生成不同中文表达，覆盖“先/随后/之后/接着/再”等顺序词，以及高度层、速度层和轨迹形态说法。

注意：程序规则可以用于生成训练标签和验证数值计算，但最终测试题的语义判定必须仍由模型完成，不能把规则输出直接当成比赛答案。

### 4.4 task1 区域理解的确定性事件引擎

区域题的计算过程适合做成可测试的状态机：

1. 将多边形构造为几何对象；
2. 对每一对相邻轨迹点检查线段与区域边界的关系；
3. 在跨边界时按线性插值估计进入/离开时间；
4. 维护 outside -> inside 和 inside -> outside 状态；
5. 航迹起点已经在区域内时，不计作一次新进入；
6. 累加区内时长；
7. 按时间排序进入事件；同一时刻按区域输入顺序排序；
8. 把相对时间转换成题目选项使用的绝对 UTC 时间。

边界点、点在线段上和数值容差必须单独写单元测试。Shapely 文档明确区分了 contains 与 within 的边界语义，不能在实现中凭直觉替换。

模型在这一步的作用是：

- 从题干确定要比较“到访、进入次数、停留时长、进入顺序”中的哪一个；
- 理解选项里的自然语言表达；
- 在事件引擎输出的事实表上选择答案。

## 5. task2：跨模态检索的研究方案

### 5.1 研究证据

#### A. 自然语言到结构化时空查询

NALMO 面向移动对象数据库，将自然语言转换为时空数据库查询，覆盖时间区间、范围、最近邻、轨迹相似性和连接等类型；论文报告了 280 条查询的评估结果。[NALMO](https://doi.org/10.1007/s10707-023-00494-5)

该工作证明了“自然语言解析器 + 时空查询执行器”的架构可行，但其领域规则和知识库是面向特定移动对象数据库的。B01 中应改成：

- 本地模型输出受约束的查询 IR；
- 确定性执行器计算时间、数值、区域和行为事实；
- 模型根据事实和相关度完成最终排序或解释。

#### B. 文本到轨迹结构化表示

Text-to-TrajVis 将自然语言问题转换为轨迹可视化语言（TVL），其 TRCAT 流程包含候选抽取、种子结构、树扩展、LLM 生成与人工验证，并通过 TVL-RAG 和区域/时间标准化提升效果。[Text-to-TrajVis](https://aclanthology.org/2026.findings-acl.972/)

B01 不要求生成可视化代码，但该工作支持以下设计：

- 先把中文查询转成有限字段的结构化表示；
- 将区域和时间统一为标准形式；
- 对复杂查询拆成多个子条件和顺序事件；
- 用检索到的结构化事实辅助模型，而不是让模型直接凭语言猜航迹。

#### C. 初召回 + 交叉编码器重排

Retrieve Fast, Rerank Smart 研究了 bi-encoder 初步召回和 cross-encoder 重排的合作式架构。其核心思想是用便宜的表示模型扩大候选覆盖，再用更精确的交叉编码器对较小候选集打分。[Retrieve Fast, Rerank Smart](https://aclanthology.org/2022.tacl-1.29/)

B01 的 2000 条航迹并不大，但该结构仍适合：

- 先用硬约束过滤和稠密/稀疏召回；
- 再用 cross-encoder 处理“先盘旋、随后加速”等组合关系；
- 直接围绕 Recall@5 和 nDCG@10 调参。

#### D. 多功能中文向量检索

BGE-M3 同时支持稠密、稀疏和多向量检索，并支持较长输入。[BGE-M3](https://arxiv.org/abs/2402.03216)

BGE-reranker-v2-m3 是 cross-encoder：输入查询和候选文本，输出相关性分数。官方模型卡明确将其定位为 reranker，而不是向量编码器。[BGE-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)

它们适合做 task2 的候选排序，但不能替代时间、区域、速度等硬条件计算。

### 5.2 推荐的 task2 处理链

#### 第一步：轨迹库离线标准化

将 02_tracks.csv 按航迹编号分组：

- 按绝对 UTC 时间排序；
- 删除重复时间或重复点；
- 标记大时间间隔和明显异常点；
- 计算轨迹摘要和行为事件；
- 为每条轨迹保存结构化 JSON 和一段可检索文本。

建议摘要字段：

- 起止时间、持续时间；
- 经纬度包围盒；
- 高度和速度的 min/max/均值/分位数；
- 加速/减速区间；
- 直线、转弯、盘旋、绕飞候选段；
- 经过的候选区域和进入/离开时间；
- 按时间排列的行为事件序列。

2000 条轨迹规模适合先做精确扫描和本地索引，不必一开始引入向量数据库。

#### 第二步：查询解析为受限 IR

示意字段：

    time:
      start: ...
      end: ...
    altitude:
      min: ...
      max: ...
    speed:
      min: ...
      max: ...
    regions:
      positive: [...]
      negative: [...]
    behavior_sequence:
      - behavior: ...
        order: 1
      - behavior: ...
        order: 2
    top_k: 10

模型只输出这类有限结构，不直接输出航迹编号。对 JSON 做 Pydantic 校验，字段缺失或范围不合法时回退到修复提示或保守解析。

#### 第三步：硬约束过滤

按以下顺序过滤：

1. 时间范围；
2. 高度和速度范围；
3. 正向区域关系；
4. 否定区域关系；
5. 已识别的行为必需条件。

“没有区域约束”与“明确要求不经过某区域”必须区分。否定条件不能通过简单地从文本中删除区域词来处理。

#### 第四步：候选召回和重排

建立三种可比较的基线：

1. 结构化精确基线：全部条件由特征表计算，按满足条件数量和距离排序；
2. BGE-M3 混合召回：对轨迹摘要做稠密 + 稀疏召回，再和硬约束结果合并；
3. cross-encoder 重排：对前 50—100 个候选，将“原始查询 + 轨迹结构化摘要”输入 BGE-reranker-v2-m3 或本地主模型，排序后截取 top_k。

推荐最终使用“硬过滤优先、语义重排补充”的排序分数，而不是让向量相似度覆盖硬条件。例如：

- 不满足必需时间/区域条件的候选直接淘汰；
- 满足全部硬条件的候选按行为顺序匹配度、数值距离和语义相关度排序；
- 对没有明确硬条件的查询，再提高向量召回和 cross-encoder 分数的权重。

### 5.3 task2 的训练数据策略

官方仅提供 50 条检索问题，建议使用航迹库自动生成弱监督查询：

- 从一条轨迹的摘要事实生成正查询；
- 从相邻轨迹或行为相似轨迹生成 hard negative；
- 随机组合时间、高度、速度、区域和行为顺序；
- 专门生成否定条件和多区域条件；
- 用事实执行器校验查询与正例是否一致。

训练/验证划分应按航迹或场景划分，不能把同一条航迹的相邻点随机拆到训练和验证中，否则会高估效果。

## 6. 哪些路线不建议作为第一版

### 6.1 让大模型直接阅读全部原始点位

风险：

- 输入长度大；
- 数值比较、时间插值和边界判断容易出错；
- 同一问题多次运行可能产生不稳定答案；
- 无法清楚定位是解析、几何还是语义环节出错。

改进：把原始点位先转换成统计特征、事件和片段摘要；只在必要时把少量局部点位作为证据补充。

### 6.2 只用固定规则直接回答

风险：

- 规则可以做时间、几何和数值运算，但不能承担题目要求的主要语义理解；
- 中文表达变体、阶段顺序和选项语义会快速超过规则覆盖范围；
- 与 B01 对模型语义判断的约束不一致。

改进：规则作为工具和弱监督标签生成器，模型负责解析和语义判别。

### 6.3 只用向量相似度做 task2

风险：

- “不经过区域 E”属于逻辑约束，单纯相似度无法保证；
- 高度/速度的区间关系可能被文本相似度掩盖；
- 顺序关系“先 A 后 B”不是普通关键词共现。

改进：先硬过滤，再向量召回和交叉编码器重排。

### 6.4 用 50 条 stage1 题直接微调大模型

风险：

- 样本量太小；
- 题目可能只是开发样例，不能代表正式测试分布；
- 容易记住题面表达而不是学习轨迹语义。

改进：用全量航迹做自监督表征，用程序生成和人工抽检扩充弱监督数据，stage1 主要用于验证和错误切片。

## 7. 建议的实验顺序

### 阶段 A：可验证的确定性底座

- 完成 UTC/相对时间处理；
- 完成轨迹排序、去重、异常标记；
- 完成距离、速度、航向、转弯率、高度变化等特征；
- 完成多边形进入/离开/停留/顺序状态机；
- 用人工构造的边界案例验证。

### 阶段 B：task1 规则辅助 + 本地模型基线

- 用变化点候选生成片段摘要；
- 用 Qwen2.5-3B 或 Qwen3-1.7B 做选项判别；
- 先测分段题和区域题的整体准确率；
- 记录错误类型：时间换算、边界事件、行为识别、选项语义。

### 阶段 C：task2 结构化检索基线

- 查询解析为 IR；
- 硬过滤；
- 结构化事实排序；
- 计算 Recall@5、Recall@10、nDCG@10；
- 以题目 top_k 为最终输出长度。

### 阶段 D：检索增强

- 加入 BGE-M3 混合召回；
- 对 top 50—100 用 BGE-reranker-v2-m3；
- 比较“纯结构化”“结构化 + BGE”“结构化 + BGE + reranker”；
- 检查是否违反专用模型数量和参数限制。

### 阶段 E：自监督和弱监督

- 用 ATSCC/TrajCL/TrajRCL 思路在无标签航迹上预训练；
- 用程序生成的正负样本微调行为识别和相似性排序；
- 只在离线验证集上决定是否保留复杂模型。

## 8. 评测设计

### task1

至少报告：

- 分段理解准确率；
- 区域理解准确率；
- 按题目中是否含绝对时间、多个阶段、重复进入、边界事件分片；
- 每个错误对应的中间事实：候选切分、事件表、模型选项概率或解析结果。

### task2

至少报告：

- Recall@5；
- Recall@10；
- nDCG@10；
- top_k 长度和轨迹编号格式通过率；
- 按查询是否包含时间、否定、多区域、行为顺序进行切片。

建议增加鲁棒性切片：

- 航迹点数短/长；
- 时间间隔均匀/不均匀；
- 只有硬条件/只有语义条件/混合条件；
- 单区域/多区域；
- 正向区域/否定区域；
- 单行为/行为序列。

## 9. 最终路线建议

在当前数据和约束下，建议把路线定为：

1. 主线架构：本地开放权重模型 + 轨迹特征/事件工具 + 结构化查询 IR + 离线检索。
2. task1：变化点候选检测 → 片段摘要 → 本地模型判别；区域题共用几何事件引擎。
3. task2：查询 IR → 时间/数值/区域硬过滤 → 结构化或 BGE-M3 召回 → cross-encoder 重排。
4. 数据策略：全量无标签航迹做自监督；程序生成查询和阶段序列做弱监督；stage1 只做开发验证和错误分析。
5. 首版模型策略：在当前 transformers==4.41.2 环境下优先验证 Qwen2.5-3B；若调整依赖后再比较 Qwen3-1.7B/4B。
6. 合规策略：在赛方确认专用模型计数前，先保留“一个主模型 + 确定性工具”的可提交基线；BGE-M3 和 reranker 作为可插拔增强模块。

这个路线的依据是：task1 的核心难点是时序变化和空间事件，task2 的核心难点是自然语言到结构化时空约束以及候选排序；已有研究分别为变化点分段、自监督轨迹表征、自然语言时空查询、混合检索和交叉编码器重排提供了方法依据，但没有任何单篇论文可以直接替代 B01 的数据清洗、约束适配和提交格式实现。
