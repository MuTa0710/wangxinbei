# B01 task1/task2 结合调研与 EDA 的整体解决思路

## 1. 结论

结合已有论文调研、B01 赛题约束和 stage1 EDA，最合理的路线是：

> **确定性时空计算负责把轨迹事实算准，本地开放权重模型负责理解中文语义、组织查询和判别选项；两者通过结构化中间表示连接。**

不建议采用以下两种极端方案：

- 让大模型直接阅读全部原始点位并完成数值、几何和排序；
- 用固定规则直接替代题目的主要语义判断。

推荐系统分成四层：

1. **轨迹标准化层**：排序、去重、异常标记、时间统一、派生运动特征；
2. **时空事实层**：变化点、轨迹片段、区域进入/离开、行为事件和轨迹摘要；
3. **本地模型层**：题意解析、查询 IR 生成、阶段语义判别、选项判断、候选语义重排；
4. **输出与评测层**：严格生成 JSONL，并按 task1 准确率、task2 Recall@5、Recall@10、nDCG@10 评测。

## 2. 数据和调研给出的事实依据

### 2.1 EDA 结果

| 事实 | 结果 | 对方案的影响 |
|---|---:|---|
| task1 分段题 | 50 条，50 条唯一轨迹 | 适合验证和错误分析，不适合直接训练大模型 |
| task1 区域题 | 50 条，区域数为 2/4/6 | 必须实现多区域事件统计 |
| task2 检索题 | 50 条，top_k 为 10—15 | 输出长度必须由输入控制 |
| task2 航迹库 | 2,000 条、483,657 个点 | 可以离线预计算全部轨迹摘要 |
| 航迹点数 | 中位数 235，范围 25—1,101 | 不应把原始点位全部作为模型文本输入 |
| 原始时间顺序 | 502 条航迹存在相邻时间倒序 | 加载后必须按航迹编号和时间排序 |
| CSV 字段 | 编号、时间、经度、纬度、高度、速度 | task2 没有航向角，需要从位置序列推导 |
| 异常值 | 存在负高度、零速度和高速点 | 要保留异常标记，不能简单全部删除 |
| task2 查询 | 时间 40/50、区域 40/50、顺序词 30/50 | 是时空约束检索，不是普通文本相似度检索 |
| 否定查询 | 7/50 | 必须显式建模负向区域条件 |
| 行为词 | 盘旋 26/50、绕飞 26/50、加速 24/50 | 需要行为事件和顺序匹配 |

### 2.2 调研给出的可借鉴方法

- SEMANTIC-SEG 支持“变化点检测 → 语义分段”的两阶段思路，适合 task1 分段；
- ATSCC、TrajCL、TrajRCL 说明在没有公开标签时，可以先做轨迹自监督表征；
- NALMO 和 Text-to-TrajVis 支持“自然语言 → 结构化时空表示 → 执行”的架构；
- Retrieve Fast, Rerank Smart 支持“初召回 → cross-encoder 重排”；
- BGE-M3 可作为中文稠密/稀疏检索候选，BGE-reranker-v2-m3 可作为候选重排器；
- Shapely 等几何工具适合实现区域事件计算，但只能作为确定性工具，不能替代 B01 要求的主要语义理解。

## 3. 总体系统结构

建议的离线推理流程如下：

    原始输入
        |
        v
    数据解析与标准化
        |
        +--> task1 轨迹特征 / 片段 / 区域事件
        |
        +--> task2 航迹摘要 / 行为事件索引
        |
        v
    本地模型解析中文题意
        |
        v
    结构化中间表示 IR
        |
        +--> task1 选项语义判别
        |
        +--> task2 硬约束过滤
                         |
                         v
                   候选召回与重排
                         |
                         v
                    JSONL 输出

核心设计是：模型不直接决定几何交点、时间差或数值区间是否满足，而是调用或读取已经计算好的事实；模型负责理解题目表达、行为概念和选项含义。

## 4. 统一数据底座

### 4.1 标准轨迹对象

对 task1 和 task2 统一生成以下内部对象：

- trajectory_id；
- 原始时间戳；
- UTC 时间；
- 相对时间；
- 经度、纬度、高度、速度；
- 派生航向角；
- 相邻时间间隔；
- 水平距离和三维距离；
- 速度变化、加速度和高度变化率；
- 转向角、转弯率和局部曲率；
- 数据质量标记。

task1 已给出航向角，应保留原字段并与由位置推导的航向进行比较。task2 没有航向角，应统一使用由相邻点计算的航向。

### 4.2 清洗规则

建议把清洗分为“排序”和“标记”两类：

1. 按轨迹编号分组；
2. task1 按相对时间排序，task2 按 UTC 时间排序；
3. 对完全重复点和重复时间点进行标记；
4. 对过大的时间间隔单独标记，不直接插值覆盖；
5. 对负高度、零速度、高速点保留原始值和异常标志；
6. 对航向角差分采用 0/360 环绕处理；
7. 任何删除或插值都保留处理日志。

不要因为一个点的高度或速度异常就直接删除整个轨迹。B01 题目可能正是利用阶段变化和异常运动模式进行判断。

### 4.3 派生特征

每个点和窗口建议计算：

- dt：相邻时间间隔；
- horizontal_distance；
- vertical_delta；
- speed_delta；
- acceleration；
- altitude_rate；
- wrapped_heading_delta；
- turn_rate；
- local_curvature；
- straight_line_error；
- local displacement ratio；
- local circle/orbit score。

这些特征既可以输入变化点算法，也可以转换成给本地模型阅读的结构化摘要。

## 5. task1 解决思路

task1 实际包含两个不同子问题：

- 分段理解：识别轨迹阶段及其顺序；
- 区域理解：识别航迹与多个多边形之间的事件关系。

两者共用轨迹标准化和运动特征，但不能使用完全相同的推理流程。

### 5.1 task1 分段理解

#### 第一步：候选变化点

使用多变量窗口特征检测候选阶段边界：

- 高度变化率显著变化；
- 速度或加速度显著变化；
- 航向变化和转弯率显著变化；
- 直线误差、曲率或局部位移模式发生变化；
- 采样间隔变化只作为质量信号，不直接作为行为标签。

第一版可先比较：

1. 固定窗口统计量差异；
2. 多变量变化点检测；
3. 自监督轨迹表征上的变化点检测。

不建议第一版直接训练复杂端到端分段网络。应先验证候选边界是否落在明显的运动模式变化附近。

#### 第二步：片段摘要

每个候选片段生成结构化摘要：

- 起止相对时间和绝对时间；
- 点数和持续时间；
- 高度起点、终点、均值、变化方向；
- 速度起点、终点、均值、变化方向；
- 航向变化总量；
- 转弯率、曲率、直线拟合误差；
- 盘旋/绕飞候选分数；
- 是否存在区域交互；
- 数据质量标记。

模型输入优先使用这些摘要，必要时再补充局部原始点位。

#### 第三步：语义判别

本地模型需要完成：

- 识别阶段语义；
- 理解“先、随后、之后、再”等顺序；
- 比较题干与 A/B/C/D 选项；
- 输出一个选项字母。

建议模型输出受约束的结构：

    {
      "阶段序列": [
        {"开始": 0, "结束": 1, "语义": "直线飞行"},
        {"开始": 1, "结束": 2, "语义": "盘旋绕飞"}
      ],
      "答案": "B"
    }

最终提交时只保留官方要求的答案字段。中间结构用于调试和错误分析。

#### 训练数据

由于 stage1 没有公开答案，不应直接用这 50 道题微调大模型。建议：

1. 生成直线、巡航、爬升、下降、加速、减速、盘旋、绕飞及组合轨迹；
2. 加入采样不均匀、缺点和噪声；
3. 由生成过程保留真实阶段标签；
4. 自动生成不同中文表述；
5. 对边界样本人工抽查；
6. 用真实 stage1 题做开发验证和 hard case 分析。

规则可以用于生成训练标签和候选边界，但不能在最终测试时直接由规则映射到选项答案。

### 5.2 task1 区域理解

#### 区域事件引擎

每个轨迹和每个多边形生成：

- 起点是否在区域内；
- 线段是否穿越区域边界；
- 进入时间；
- 离开时间；
- 单次停留时长；
- 累计停留时长；
- 区外进入次数；
- 进入事件序列。

建议使用状态机：

    outside -> inside：记录进入事件
    inside -> outside：记录离开事件
    inside -> inside：继续累计停留
    outside -> outside：无事件

跨界点的时间可以用相邻轨迹点的线性插值估计。对于边界点、切线、重复进入和起点已在区域内的情况，必须设置明确的容差和测试用例。

#### 模型作用

模型不负责重新计算交点，而负责：

- 识别题目要求的统计类型；
- 理解“累计停留”“从区外进入次数”等表达；
- 读取区域事件表；
- 判断哪个选项与事实一致。

这种方式同时满足数值可验证性和中文语义泛化要求。

## 6. task2 解决思路

task2 应拆成“查询理解、候选过滤、候选排序、格式输出”四个阶段。

### 6.1 航迹库离线预处理

对 2,000 条航迹一次性计算：

- 起止 UTC 时间和持续时间；
- 经纬度包围盒；
- 高度和速度统计；
- 速度/高度变化段；
- 派生航向、转弯率、曲率；
- 直线、盘旋、绕飞候选事件；
- 与预定义区域的进入/离开事件；
- 行为事件时间序列；
- 数据质量摘要。

同时保存两种表示：

1. 机器可执行的结构化 JSON；
2. 用于向量检索或 reranker 的中文/英文结构化文本摘要。

2,000 条轨迹规模不大，第一版可以完整扫描和本地缓存，不必先引入向量数据库。

### 6.2 查询 IR

本地模型把中文查询转换为受限结构：

    {
      "时间": {"开始": "...", "结束": "..."},
      "高度": {"最小": null, "最大": null},
      "速度": {"最小": null, "最大": null},
      "区域": {
        "经过": ["区域 A"],
        "不经过": ["区域 E"]
      },
      "行为序列": [
        {"行为": "盘旋绕飞", "顺序": 1},
        {"行为": "加速", "顺序": 2}
      ],
      "top_k": 10
    }

需要区分：

- 没有区域条件；
- 要求经过区域；
- 要求不经过区域；
- 同时存在正向和负向区域条件。

IR 必须经过 JSON schema 或 Pydantic 校验。模型输出非法时，先进行一次修复；仍失败则使用保守解析并记录错误。

### 6.3 硬约束过滤

优先执行可验证的条件：

1. 时间范围；
2. 高度范围；
3. 速度范围；
4. 正向区域关系；
5. 负向区域关系；
6. 已明确的行为必需条件。

硬约束不满足的航迹直接淘汰。这样可以避免向量相似度把“不经过区域 E”误排成满足条件。

### 6.4 行为顺序匹配

将查询行为和航迹行为都表示为带时间的事件：

    event = {
      "type": "盘旋绕飞",
      "start": t1,
      "end": t2,
      "confidence": 0.82
    }

对“先 A，随后 B”检查：

- A 是否存在；
- B 是否存在；
- A 的结束时间是否早于 B 的开始时间；
- 两个事件之间是否允许间隔；
- 事件识别置信度是否足够。

首版可以采用可解释的分数：

    behavior_score =
        event_presence_score
        + order_score
        + temporal_overlap_score
        + feature_similarity_score

模型只对行为概念和表达做语义补充，时间顺序仍由事件时间戳验证。

### 6.5 候选召回和重排

建议建立三个逐步增强的基线：

#### 基线 A：纯结构化

- 只使用硬条件和结构化特征；
- 对满足全部条件的轨迹按数值距离、行为匹配和事件顺序排序；
- 优点是可解释、容易合规。

#### 基线 B：结构化 + BGE-M3

- 先硬过滤；
- 用轨迹摘要进行稠密/稀疏召回；
- 合并结构化候选和语义候选；
- 比较 Recall@5、Recall@10 和 nDCG@10。

#### 基线 C：结构化 + 召回 + reranker

- 对前 50—100 个候选使用 cross-encoder；
- 输入为“原始查询 + 候选航迹摘要”；
- 只在候选规模较小时执行；
- 最终按输入 top_k 截取。

不能让 reranker 推翻必需硬条件。语义相关度只能决定满足硬条件候选之间的顺序。

## 7. 无标签数据下的训练方案

### 7.1 自监督轨迹表征

使用全量 2,000 条航迹进行：

- 时间片段裁剪；
- 轻微位置扰动；
- 掩码重构；
- 相邻片段对比；
- 同一轨迹不同视图对比。

增强必须保持运动语义。例如不能把时间顺序打乱，也不能让高度和速度变化与轨迹形态失去对应关系。

ATSCC、TrajCL 和 TrajRCL 的共同启发是：在缺少人工标签时，先学习轨迹结构表示，再用少量弱标签完成下游任务。

### 7.2 程序生成弱监督

从已知生成过程构造：

- 分段阶段标签；
- 区域进入/离开事实；
- 查询正例航迹；
- hard negative 航迹；
- 多条件组合查询；
- 否定区域查询；
- 行为顺序查询。

生成样本必须经过事实执行器校验，避免出现文本与轨迹不一致的伪标签。

### 7.3 人工小规模高质量标注

建议人工标注一套内部验证集：

- task1 分段边界和阶段序列；
- task1 区域事件表；
- task2 查询的结构化 IR；
- task2 正例、负例和排序偏好。

这套数据不用于替代官方测试，而用于定位问题和比较模型。对于 50 条 stage1 样例，可以逐条做双人复核或至少二次复核，形成可重复的内部 gold。

## 8. 模型配置建议

### 8.1 首版保守配置

- 一个 Qwen2.5-3B-Instruct 作为本地语义模型；
- 确定性轨迹和几何工具；
- 结构化字典/倒排索引；
- 不加入额外学习模型。

原因：

- 当前 proj 环境固定 transformers 4.41.2；
- Qwen3 官方模型卡要求更高 Transformers 版本；
- 可以先验证完整流程和合规性；
- 便于定位问题是数据、工具还是模型。

### 8.2 增强配置

待首版稳定后比较：

- Qwen3-1.7B 或 Qwen3-4B；
- BGE-M3 进行候选召回；
- BGE-reranker-v2-m3 进行候选重排；
- 轻量时序编码器或自监督轨迹编码器。

B01 对专用模型数量和参数量有限制。Qwen、BGE-M3 和 reranker 是否全部计入专用模型，需要向赛事方确认。未确认前，应始终保留“一个主模型 + 确定性工具”的可提交版本。

## 9. 评测和实验设计

### 9.1 task1 指标

- 分段题准确率；
- 区域题准确率；
- 时间换算错误率；
- 变化点偏差；
- 区域进入/离开事件误差；
- 按短/长轨迹、异常点、区域数量分片。

### 9.2 task2 指标

- Recall@5；
- Recall@10；
- nDCG@10；
- top_k 长度正确率；
- 航迹编号唯一性和格式通过率；
- 按时间、区域、否定、多区域、行为顺序分片。

### 9.3 消融实验

至少比较：

1. 纯模型直接读原始点位；
2. 特征摘要 + 模型；
3. 特征摘要 + 几何事件 + 模型；
4. 结构化 task2；
5. 结构化 + BGE-M3；
6. 结构化 + BGE-M3 + reranker。

目标不是一开始追求复杂，而是确认每个模块是否实际提升结果。

## 11. 关键风险和处理方式

| 风险 | 表现 | 处理 |
|---|---|---|
| 直接让模型读原始点位 | 数值和边界判断不稳定 | 先生成事实表和摘要 |
| 规则替代语义 | 对表达变体泛化差，也有合规风险 | 规则只计算事实，模型做语义理解 |
| CSV 未排序 | 事件顺序和速度计算错误 | 每条航迹先按 UTC 排序 |
| CSV 没有航向角 | 无法直接分析转弯 | 从经纬度和时间推导 |
| 异常值误删 | 可能丢失真实阶段或导致轨迹断裂 | 保留原值并增加质量标记 |
| 仅用向量相似度 | 否定和数值条件错误 | 硬过滤优先 |
| 50 条题直接微调 | 过拟合题面 | 合成数据、自监督和人工验证 |
| 专用模型超限 | 提交时合规风险 | 先使用单主模型配置并确认口径 |

## 12. 推荐的最终形态

最推荐的第一版系统是：

> 统一轨迹标准化  
> → 运动特征和区域事件计算  
> → 本地 Qwen2.5-3B 生成 task2 查询 IR、理解 task1 题意和选项  
> → task1 使用片段/事件事实判别  
> → task2 使用硬过滤和结构化排序  
> → 通过内部评测后再加入 BGE-M3 和 reranker

这样做的理由是：

1. 符合 B01 的本地模型和工具边界；
2. 直接针对 EDA 发现的时间倒序、缺少航向、异常值和组合查询问题；
3. 每一步都有中间结果，便于定位错误；
4. 首版可以在没有官方 GT 的情况下通过合成数据、弱监督和人工验证推进；
5. 后续可以逐步增加自监督表征和检索重排，而不需要推翻整体架构。
