# M4 Task1 与 M5 统一运行器

## M4 Task1

M4 读取 M1 的 Task1 标准化轨迹：

- 分段题按选项所需的阶段数量切分轨迹，提取高度、速度和空间运动摘要；
- 区域题复用 M2 的区域事件事实，核对到访、进入/离开时刻、停留时长、进入次数和区域顺序；
- 默认使用可解释的确定性四选一基线；
- 通过 `--backend qwen3 --model-name ...` 可切换到本地 Qwen3 四选一适配器；
- 无模型权重时不影响默认基线运行。

运行：

```bash
python scripts/build_m4_task1.py \
  --cache-dir artifacts/m1 \
  --output artifacts/m4 \
  --backend deterministic
```

输出：

- `task1_baseline_results.jsonl`：100 条 Task1 结果；
- `task1_facts.jsonl`：轨迹阶段和区域事件事实；
- `task1_diagnostics.jsonl`：选项分数和后端记录；
- `manifest.json`：样本数和选项分布。

## M5 统一运行器

M5 将 M3 的 Task2 结果和 M4 的 Task1 结果按官方样本顺序合并，生成：

```text
artifacts/m5/traj_result.jsonl
```

同时运行：

- 样本覆盖检查；
- Task1 选项格式检查；
- Task2 序号连续和航迹编号唯一检查；
- M2 边界场景检查结果汇总；
- 提交文件 SHA256 和运行耗时记录。

运行完整 M3→M5 流程：

```bash
python scripts/run_m5_pipeline.py \
  --cache-dir artifacts/m1 \
  --work-dir artifacts \
  --output artifacts/m5
```

如果只需要复用已经生成的 M3/M4 缓存：

```bash
python scripts/run_m5_pipeline.py --reuse
```

报告文件为 `artifacts/m5/m5_report.json`。`artifacts/` 已被 Git 忽略，不会把数据缓存和提交产物提交到仓库。
