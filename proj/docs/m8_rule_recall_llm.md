## 0. 结论先行（TL;DR）

1. **召回改为“规则相似度 → Top-2K → 模型”**：对 2,000 条航迹逐条算可解释相似度，按分数取 `2×top_k`（当前 top_k∈[10,15] → 池 20–30 条，均值 24.6），硬过滤通过项强制入池。这满足“偏 recall + 让模型判断”。
2. **日期题的召回先验必须显式处理，否则 2×池会漏掉当天的批次尾巴**：
   - `2025-01-01` 查询：严格时间窗 00:00–06:00 只剩 4 条；但当天批次有 10 条，其中 `06:00:01/02` 只差 1–2 秒，`09:30×2` 差 3.5 小时，`12:00×2` 差 6 小时；
   - 给“同一天但时间窗外”一个相似度信用（`same_date_credit=0.8`）后，10 条里 **9 条**进入 2×池（214 m/s 那条因明显不符低速被挤出）；40 个日期题平均 **9.47/10** 入池，date-batch recall@10 = **0.948**；
   - 不给信用时，只有严格 4 条入池，平均 **5.95/10**，date-batch recall@10 只有 **0.527**。
   - 结论：按你“偏 recall”的要求，**默认给日期信用**；模型再从池里剔除明显冲突项（例子见 3.2）。
3. **行为主导题（无日期/弱时间约束）是真正的短板，根因是行为特征，不是“没有时间”**：
   - 时间不是硬门，缺时间也不会扣分；无日期题只是 active 约束少、行为项在相似度里的权重占比更高；
   - 以 `retrieval_000034`（无日期/区域/高度/速度，只要求“先爬升→顿挫阶梯加速→盘旋”，top_k=14）为例：M3 硬过滤通过全部 2000 条，行为是唯一判据；
   - 但 M3 的行为 flag 太松：`orbit` 命中 **1546/2000（77%）**、`abrupt_step_accel` 命中 1159 条，查询要求的三个 flag 交集 **432 条**，全部同分 1.0；
   - 2×池只有 28 条，432 并列类里随机取 28 条，共识 gold 14 条只有 **1 条**在池内（随机期望 28×14/432≈0.9）；模型看不到的候选不可能被选出来；
   - 把池放大到 4×（56 条）也只覆盖 432 的 13%，不是解法。**必须补事件级行为检测**（3.3），而不是简单调阈值或加池子。
4. **模型直接输出官方结构**，例如：
   ```json
   {"样本编号":"retrieval_000001","结果":[{"序号":1,"航迹编号":"traj_000256"},{"序号":2,"航迹编号":"traj_000685"}]}
   ```
   runtime 校验 `样本编号`、`结果` 列表、`序号` 连续、`航迹编号` 不重复且在候选池内、长度 ≤ top_k；不合法 → 带错误回喂重试 1 次 → 仍不合法回退规则序（也是官方结构）。**不再使用 picks/rank 中间格式。**
5. **现状审计未变**：M3 严格过滤后候选中位数 6.5、40/50 不足 top_k；M7 平均返回 5.84/12.28（空位 52%）；M7 strict JSON 100%、fallback 0——瓶颈始终在召回，不在 JSON。

## 3. 规则相似度召回（M8.0）

### 3.1 相似度定义

对每条航迹，只对查询中**实际出现的约束**计分，最后做加权平均（0–1，越大越相似）：

```text
sim = Σ(w_i × s_i) / Σ(w_i)          # 只对 active 约束求和

active 约束与权重：
  time      2.0   时间窗内=1.0；同日窗外=same_date_credit（默认 0.8）；
                  其他日期=0.0；无日期时按窗外小时数衰减
  altitude  1.5   区间内=1.0；越界按 margin/区间宽度线性衰减
  speed     1.5   同上
  region    2.5   正区域命中比例；负区域命中 → 直接淘汰（一票否决）
  behavior  2.0   行为序列命中比例（当前用 M3 behavior_score；M8.0b 改为事件级模式分）
```

> **缺项不扣分**：查询里没有的约束不进入分母。无日期题只是没有 `time` 项，相似度在高度/速度/区域/行为之间归一化；不会因为“没时间”给任何候选判失败，也不会给所有候选扣分。

补充规则：

- **负区域命中一票否决**（“不满足/不经过”语义），无论分数多高都不进池；
- **硬过滤通过项强制入池（有条件）**：当硬过滤通过项数量 ≤ `2×top_k` 时，保证它们全部入池（挤掉同数量的最低分非硬通过项）；若硬过滤通过项本身超过 `2×top_k`（例如无日期/无区域题会 2000 条全通过），则退化为“按相似度取前 2×top_k”，避免池被撑爆；
- 所有分数、失败原因、证据写入 `pools.jsonl`，可复现、可审计；
- 之后可把行为项升级为“事件级模式匹配”（M8.0b 的关键工作，见 3.3）。

#### 3.1.1 执行顺序（M8）

M8 只有**一条真正的硬淘汰规则：负区域命中**。其余时间/高度/速度/正区域/行为都不提前淘汰，只进入相似度打分。执行顺序固定为：

```text
1. 解析 IR，确定 active 约束集合（查询里没出现的约束不参与分母）
2. 负区域 veto：命中任一 negative_regions → 直接排除（最便宜、语义最确定）
3. 对剩余 2,000 条逐条计算（不做 early-exit）：
   a. 时间项：日期/时间窗 + same_date_credit
   b. 高度项：高度中位数 vs 区间
   c. 速度项：速度中位数 vs 区间 / low_speed flag
   d. 正区域项：正区域命中比例
   e. 行为项：M3 behavior_score（M8.0b 换成事件级模式分）
   f. 质量惩罚：q=1 扣分
   g. 同步用 M3 hard_filter 记录 fail（顺序见下）
4. 按 sim 降序、traj_id 升序（稳定排序，保证可复现）
5. 取前 2×top_k；若 hard-pass 数量 ≤ 2×top_k，把漏掉的 hard-pass 换入
6. 生成候选卡
```

其中第 3.g 步复用 M3 `hard_filter` 的判定顺序（`baseline.py:295-319`）：

```text
time          起始时间是否落在时间窗内（只看 start_time_utc）
altitude      高度中位数是否落在高度区间
speed         速度中位数是否落在速度区间
positive_reg 正区域是否命中（缺失即 fail）
negative_reg  负区域是否命中（命中即 fail）
low_speed     flags.low_speed 且平均速度 > 100 即 fail
very_high     flags.very_high_altitude 且平均高度 < 8000 即 fail
```

这七项是 **AND 关系，全部收集**（不短路），所以顺序只影响 `fail` 列表和图审计，不影响最终“是否 hard-pass”；`behavior` 不在 hard_filter 里，只做排序分。

> 口径提醒：M3 `hard_filter` 对 `flags.low_speed` 用的是“平均速度 > 100 即 fail”，而 M7 的 `search_tracks` 在 flag 为真时会把速度上限收紧到 80。M8 建议统一按 80 处理：flag 为真时先把 `speed_range_mps=(0,80)` 写进 IR，再调用 `hard_filter`，避免同一题出现两套低速口径。

**为什么不把时间/高度/速度过滤放在相似度之前？**

- 如果先按时间硬淘汰，`same_date_credit` 要救的 `06:00:01`、`09:30`、`12:00` 这批当天航迹会先被删掉，日期召回直接回退到 0.507；
- 如果先按高度/速度硬淘汰，区间边缘的候选会被删掉，“2×池 + 模型判断边缘”就失去意义；
- 所以 M8 的顺序是“**负区域先 veto，其余全部软打分，hard-pass 只用于生成 fail 和强制入池**”；
- 如果比赛后期确认必须“硬过滤优先”，再加一个 `strict_first` 模式（先 strict 集，再补 relaxed），作为对照，不作为默认。

性能上，2,000 条 × 每条约 5 个 O(1) 计算，单题是毫秒级；M3 的 36 秒主要花在特征计算和区域命中缓存，不在过滤本身。

### 3.3 行为主导题为什么不行（以 `retrieval_000034` 为例）

**先澄清一个误解：无日期本身不是失败原因。** M8 里时间不是硬过滤，缺时间也不会扣分；无日期题的失败是因为 active 约束少，行为项成了主要判据，而当前行为项没有区分度。给这类题硬塞一个“假日期”也救不了 432 条并列——必须把行为特征做细。

**查询**：`筛选出飞行航迹，要求其先爬升，随后顿挫阶梯型加速，最后盘旋绕飞。`（top_k=14）

这道题**没有日期、没有区域、没有高度/速度区间**，所以：

- M3 硬过滤通过 **全部 2000 条**；
- 相似度只剩“行为”一项，行为相似度就是唯一判据；
- 一旦行为特征不区分，池子就只能随机取。

**问题 1：M3 的行为 flag 阈值太松，命中率极高。**

| flag | 命中数 / 2000 | 命中率 | M3 判定条件（摘要） |
|---|---:|---:|---|
| `orbit` | **1546** | **77.3%** | `circularity>=2` 或 `total_turn>=1000° 且 path>20km` |
| `step_accel` | 1362 | 68.1% | 分段速度最大正变化 >5 m/s |
| `abrupt_step_accel` | 1159 | 58.0% | 分段速度最大正变化 >10 m/s |
| `long_platform_step_accel` | 1350 | 67.5% | 正加速 >5 且 speed_std<80 |
| `climb` | 809 | 40.5% | 分段高度最大正变化 >100 m |
| `periodic_speed` | 385 | 19.3% | speed 正负变化 ≥3 次且 std≥3 |

`orbit` 77% 的命中率是致命点：大多数长航迹累计转弯都会超过 1000°，于是“盘旋绕飞”这个条件几乎筛不掉人。

**问题 2：三行为交集 432 条，全部同分 1.0，2×池只能随机取。**

- `climb + abrupt_step_accel + orbit` 交集 = **432 条**，行为相似度全部 1.0；
- 2×top_k = **28 条**，并列时只能按 id 排序取前 28；
- 共识 gold 14 条里只有 **1 条**落在这 28 条里；随机期望是 `28×14/432≈0.9`，实测与随机一致；
- 池放大到 4×（56 条）随机期望也只有 `56×14/432≈1.8`，仍然不可能覆盖 14 条 gold。

**问题 3：flag 把“看起来像”和“真是这个模式”混为一谈。**

以 `retrieval_000034` 为例（M3 特征中位数）：

| 指标 | 共识 gold（14 条） | 2×池内候选（28 条） | 432 并列类 |
|---|---:|---:|---:|
| `dAlt+`（最大爬升，m） | 317 | 731 | 653 |
| `dSpd+`（最大加速，m/s） | **9.8** | **20.4** | 23.2 |
| `spd_std`（速度标准差） | **9.5** | **68.8** | 71.8 |
| `circ`（盘旋比） | 2.68 | 2.49 | 4.17 |

gold 更像“有清晰台阶、速度平稳的阶梯加速 + 盘旋”；池里大量候选是“速度抖得厉害、但刚好越过阈值”的噪声航迹。M3 的 flag 对两者都给 1.0，所以按 flag 排序无法区分。修饰词 `顿挫/急促/平缓/长平台` 描述的是**事件形态**（台阶数、单步 delta、平台长度、顺序），不是“最大 delta 更大”。

**问题 4：模型无法补救“没看到”。**

模型只看到 28/432 条；gold 的 13 条不在池里，再强的推理也选不出来。这不是模型能力问题，是召回问题。

同类现象在其他无日期题也存在：

| 样本 | 硬过滤后候选 | 相似度 1.0 并列类 | 2×池 | 池内 gold |
|---|---:|---:|---:|---:|
| retrieval_000034（无区域，三行为） | 2000 | **432** | 28 | 1/14 |
| retrieval_000022（区域 B，三行为） | 345 | 96 | 24 | 3/12 |
| retrieval_000097（区域 B，两行为） | 345 | 185 | 28 | 3/14 |
| retrieval_000109（区域 F，进近） | 216 | 85 | 22 | 4/11 |
| retrieval_000158（区域 C，周期波动） | 399 | 83 | 30 | 5/15 |
| **10 道无日期题平均** | — | 83–432 | 20–30 | **0.158** |

**结论：不是“2×top_k 不够大”，而是相似度在无日期题上没有区分度。** 单纯调阈值、把池子放到 3–4×、甚至 10×，都只是从 432 个并列里多抽几张，治标不治本。

**M8.0 的解法：事件级行为检测（不是“强度调大”）**

1. **速度台阶/平台事件检测**：对速度序列做变化点/平台检测，输出台阶数、单步 delta、平台时长、台阶间隔、是否长平台、是否规则阶梯；`顿挫` 对应“台阶多、间隔短、delta 中等”，`平缓` 对应“delta 小、间隔长”，`急促` 对应“delta 大、间隔短”；
2. **盘旋事件检测**：按滑窗检测持续转弯区间，输出盘旋段数、单段时长/占比、每圈转角、盘旋半径变化；不再用“总转角>1000°”这种全局阈值；
3. **高度爬升/下降事件**：事件起止、总落差、平台段、梯级数，区分“大落差阶梯”与普通爬升；
4. **顺序匹配**：按事件时间线匹配“先…随后…最后…”，而不是 8 个粗窗口的 stage 顺序；
5. **修饰词映射**：把 `急促/顿挫/平缓/柔和/长平台/大落差/大仰角/陡峭` 映射到上述事件属性的目标区间，行为项输出 0–1 连续分；
6. **参考实现**：`artifacts/consensus_answers/subs/task2/features2.py` 已经做了事件级检测（时间清洗、速度/高度事件、盘旋区间、6 区域命中），可直接把逻辑移植到 `b01/retrieval/behavior_events.py`，不要从零发明；
7. **验收门槛**：10 道无日期题的 2×池代理召回从 0.158 提到 **≥0.5**，且最大并列类降到与 `top_k` 同量级（<50 条）；达不到就说明事件特征仍不够细，先别接模型。

> 如果时间不够、暂时不做事件检测：这 10 题的结果基本等于随机抽 14 条，应明确标注为已知短板，不要归因于“模型不行”。

### 3.4 候选卡片（喂给模型的结构化证据）

每张卡片是航迹摘要，**不是原始点序列**（遵守“不把 48 万点交给模型”的边界）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | str | 航迹编号（模型输出也要用它） |
| `start` | str | 起始时间 `月-日 时:分[:秒]` |
| `dur` | int | 时长（秒） |
| `alt` | int | 高度中位数（m） |
| `spd` | float | 速度中位数（m/s） |
| `spd_std` | float | 速度标准差（速度保持/周期波动） |
| `dAlt` | str | 分段高度变化最大正/负值（`+爬升/-下降`，m） |
| `dSpd` | str | 分段速度变化最大正/负值（m/s） |
| `turn` | int | 航向累计变化（度） |
| `circ` | float | 路径/首尾位移（>2 盘旋） |
| `reg` | obj | 查询涉及区域命中：`{"A":1,"E":0}` |
| `fail` | obj | 未满足的约束及偏差，`{}`=全部满足；如 `{"time":"+3.5h"}`、`{"alt":"-1200m"}`、`{"beh":["orbit"]}` |
| `db` | 0/1 | 是否同日期批次（时间窗外但同日） |
| `q` | 0/1 | 数据质量异常 |

单卡约 220–260 字符，2×池 20–30 条约 **5–7 KB**，加 system prompt/IR/few-shot，整条 prompt 约 **4–5k tokens**（Qwen3-4B 32k 上下文，余量充足）。

### 3.5 召回覆盖核算（本版实测）

口径：2×top_k 按 3.1 相似度排序、`same_date_credit=0.8`、硬过滤通过项强制入池；代理真值 = `consensus_answers`。

| 分组 | 题数 | 池大小 | 代理池召回 | 规则 top_k 的 Jaccard | 其它 |
|---|---:|---:|---:|---:|---|
| 日期题 | 40 | 20–30 | **0.818** | 0.693 | 当日批次入池 9.47/10；date-batch recall@10 **0.948** |
| 行为主导题（10 道无日期） | 10 | 20–30 | **0.158** | 0.062 | 并列类 83–432；见 3.3 |
| 全部 | 50 | 20–30（均值 24.6） | 0.691 | 0.571 | — |

对照：不给日期信用时，全部池召回 0.454、日期题 5.95/10、date-batch recall@10 0.527。

> 提醒：代理真值是另一套规则解，不是官方答案；“池召回”是模型能达到的**理论上限**，不是最终准确率。日期题代理召回 0.818 已可支撑模型继续；非日期题 0.158 必须先修 3.3，否则模型无意义。

### 3.6 其他约束的松紧度：哪些能收紧，哪些一收紧就丢 gold

“432 条并列 → 把其他因素卡更严”这个直觉需要先验证：**其他因素收紧后，候选数会降，但 gold 也会不会一起被删？** 用代理真值实测（候选数按对应约束在全库 2000 条上的通过数统计）：

| 因素 | 当前规则 | 可收紧方式 | 候选数变化 | gold 通过率变化 | 结论 |
|---|---|---|---:|---:|---|
| 时间 | 日期题：起始时间在窗内；M8 另加同日信用 0.8 | 严格：去掉同日信用、只留窗内 | 日期题 | 窗内 **42.5%**；同日 **83.4%**；窗外 16.6% | 严格会丢 **57.5%** gold，不能收 |
| 高度 | 高度**中位数**在区间内 | 全段严格：`min>=lo 且 max<=hi` | 平均 942 → **705**（-25%） | **100% → 78.4%**（丢 21.6%） | 收紧丢 gold，不值 |
| 速度 | 速度**中位数**在区间内 | 全段严格：`min>=lo 且 max<=hi` | 平均 1617 → **787**（-51%） | **100% → 53.7%**（丢 46.3%） | 收紧丢 gold，不能收 |
| 区域 | 正区域命中（entry/exit/start/end 任一）；负区域一票否决 | 加停留阈值：dwell≥30s/60s | 命中数 216–485；dwell 中位数 241–602s，inside_points=0 为 0 条 | 正区域 gold **100%** 命中；负区域 gold **0%** 命中 | 已经很紧；加 dwell 对并列类几乎无影响 |
| 质量 | q=1 只扣 0.1 分 | 硬排除 q=1 | 432 并列中 142 条 q=1 → 290 条 | 全部 gold 的 q=1 比例 **32.4%**；000097 为 **12/14** | 硬卡会丢大量 gold，只能小权重惩罚 |
| 平滑度/噪声 | 未显式使用 | 要求 `spd_std`/`alt_std` 小 | 000034：432 →（<20,<200）**30**；（<30,<500）**72** | gold 保留 **6/14**、**8/14** | 可作为 tie-breaker，不能全局硬卡 |
| 行为阈值 | orbit 77%、abrupt 58% 等 | 提高阈值 | 约 400 → 232（仍 >> 28） | — | 阈值收紧不解决并列 |
| 行为顺序 | 仅 8 窗口 stage 顺序，orbit 不参与 | 事件时间线“先→随后→最后” | 未实现 | — | 需要事件级特征（M8.0b） |

**几个关键解释：**

1. **高度/速度的“中位数”不是随便选的。** 查询里的“高度 4000–7000m”“速度 60–150m/s”通常指某个飞行阶段，不是整条轨迹所有点；用全段严格会错误地删掉“只有巡航段在区间内”的合法航迹。实测 gold 只有 78%/54% 能满足全段严格，所以不能把全段严格当硬过滤。
2. **区域其实已经很紧。** 6 个区域命中数只有 216–485/2000；所有命中的航迹都有实打实的区内点（inside_points=0 为 0 条），停留中位数 241–602 秒，不存在“擦边 1 秒”的假命中。再加 dwell≥30/60s，对 96/185 这种并列类基本不减少。区域不是宽松点。
3. **质量 q=1 不能当硬过滤。** gold 里 32.4% 的航迹本身 q=1（大间隔/零速等），000097 的 14 条 gold 里 12 条 q=1；硬排除 q=1 会把 gold 一起删掉。质量只能做很小的 tie-break 惩罚。
4. **平滑度是“看起来有用、但不能硬卡”的因素。** 000034 的 432 条并列里，候选的 `speed_std` 中位数 71.8、`alt_std` 2070；gold 只有 9.5、157——差异很大，说明大量并列候选是被注入噪声抬起来的。但硬阈值 <20/<200 只能留下 30 条且只保留 6/14 gold，<30/<500 留下 72 条保留 8/14；不同 query 的合法行为本身就会带来速度/高度方差（如进近、周期波动）。所以它适合做**软惩罚/二次排序**，不适合做硬门。
5. **000034 没有其他因素可收紧。** 这道题无日期、无区域、无高度、无速度——其他因素为空，能卡的只有行为。对“区域+行为”的题（如 000022），区域已经命中并已经参与排序，剩余 96 条并列仍然只能靠行为区分。

**能安全卡严的（不会丢 gold）：**

- 负区域一票否决（gold 命中率 0%）；
- 正区域命中（gold 命中率 100%）；
- 数据有效性（非有限值、重复时间等），但只能删少量坏点航迹，救不了 432 并列。

**推荐做法：分层严格，而不是全局硬卡**

```text
第 1 层（硬门，gold-safe）：
  负区域 veto + 正区域命中 + 数据有效性
第 2 层（软分，保留 recall）：
  时间/高度/速度用中位数 + 日期信用；行为用 M8.0b 事件级模式分
第 3 层（只在并列过大时启用的 tie-breaker）：
  若最大并列类 > 2×top_k：
    1) 事件级行为分（第一优先）
    2) 平滑度/噪声惩罚（spd_std、alt_std，小幅）
    3) 质量 q=1 小惩罚（不能排除）
    4) 仍并列 → 标 ambiguous/low_confidence，可选放大池子
```

一句话：**能卡的只有“负区域/正区域/数据有效性”；时间、高度、速度、质量一旦按“候选数最少”去卡，就会把 gold 一起删掉。432 并列的解法不是把别的因素卡死，而是把行为项从二值 flag 变成事件级模式分。**

## 4. 模型层（M8.1）

### 4.1 输入构造

每个样本一次 chat 请求（system + user），不进入工具循环：

```text
system = 角色 + 卡片字段说明 + 判定规则 + 输出格式 + 2 个 few-shot
user   = 原查询 + top_k + 相似度解析回显 + 候选卡 JSONL + 输出提醒
```

模型只看到 20–30 条候选卡，不看到 2,000 条全库、不看到原始点序列。

### 4.2 system prompt（v2，直接输出官方结构）

```text
你是 B01 赛题 task2 的检索裁决器。你只能从给定候选池中挑选航迹并排序，
直接输出最终结果；不能引入池外航迹，不能编造编号，不要输出解释文字。

## 输入
- 原始查询：中文自然语言，包含时间/高度/速度/区域/行为顺序等约束。
- top_k：本次最多输出条数。
- 规则解析：规则引擎对查询的结构化理解，可能过严或漏项，仅供参考。
- 候选池：20–30 条候选，每行一个 JSON 卡片。字段：
  id=航迹编号；start=起始时间(UTC，月-日 时:分[:秒])；dur=时长(秒)；
  alt=高度中位数(m)；spd=速度中位数(m/s)；spd_std=速度标准差；
  dAlt=分段高度变化最大正/负值(m)；dSpd=分段速度变化最大正/负值(m/s)；
  turn=航向累计变化(度)；circ=路径/首尾位移比(盘旋>2)；
  reg=查询涉及区域命中(1/0)；fail=未满足约束及偏差(空=全部满足)；
  db=1 表示同日期批次；q=1 表示数据质量异常。

## 判定规则
1. 以原始查询为准，规则解析只作参考；若明显不符，按查询语义判断。
2. 第一优先选 fail 为空的候选；同级别内尽量保持候选出现顺序。
3. 不足 top_k 时才用 fail 最小的候选补位，优先级：
   时间边界(±小时级 / db=1) > 数值小幅越界(<10%) > 单一行为未命中；
   明显冲突不要补（例如查询“低速”而 spd>150）。
4. 日期题：db=1 表示同一天批次，可作为候选；但若与查询主体约束明显冲突，
   排到后面或不选。
5. 行为强弱看证据：急促看 dSpd 大，平缓看 dSpd 小；大落差/大仰角看 dAlt；
   盘旋看 turn/circ；速度保持看 spd_std；周期性看 spd_std 与 dSpd 正负交替。
6. 结果按相关度从高到低；长度 ≤ top_k；候选确实不够时宁可少给，不要凑数。
7. 只输出一个 JSON 对象，禁止 markdown 代码块、禁止前后解释文字。

## 输出格式（必须与数据集提交结构完全一致）
{"样本编号":"<原样照抄输入里的 sample_id>","结果":[{"序号":1,"航迹编号":"traj_XXXXXX"},{"序号":2,"航迹编号":"traj_XXXXXX"}]}
- 序号从 1 开始连续递增；
- 航迹编号必须来自候选池，不能重复；
- 结果按相关度从高到低排列；
- 不输出 why/解释/额外字段。
```

## 5. 最终结果契约与校验

### 5.1 模型输出契约

一行一个官方记录，字段与 `traj_result.jsonl` 完全一致：

```json
{"样本编号":"retrieval_000001","结果":[{"序号":1,"航迹编号":"traj_000256"},{"序号":2,"航迹编号":"traj_000685"}]}
```

> 以上仅列 2 条作格式示例；实际长度由模型判断（`1..top_k`）。

- `样本编号`：原样照抄输入，必须等于当前样本；
- `结果`：列表，长度 `1..top_k`；
- 每项恰好 `序号`（1 起连续）和 `航迹编号`（池内 ID、不重复）；
- **不输出** `why`、`picks`、`rank`、`confidence` 等额外字段；
- runtime 校验通过后**原样写入**，不做重排/补位/改写。

### 5.2 Runtime 校验（全部确定性）

按顺序检查：

1. 是单个 JSON 对象（strict `json.loads(raw.strip())`）；
2. 顶层键恰好 `样本编号`、`结果`（多余键拒绝，防止模型夹带解释）；
3. `样本编号` == 当前 sample_id；
4. `结果` 是列表，长度 `1..top_k`（池为空时允许 `[]`）；
5. 每项是对象，键恰好 `序号`、`航迹编号`；`序号` 为整数且 1..n 连续；
6. `航迹编号` 不重复、在 2,000 条库内、且在本次候选池内（闭集）；
7. 通过 → 写 `traj_result.jsonl`；失败 → 错误文本回喂重试 1 次 → 仍失败回退规则序。

> 官方 `validate_submission.py` 只检查 `序号` 连续和编号不重复；池内闭集是 M8 额外加的防幻觉校验。

### 5.3 数量策略（本版：模型决定）

- prompt 要求“尽量给满 top_k，除非候选不足/明显不符”；
- runtime **不补位**：模型给几条就提交几条，只在 `report.json` 记 `below_top_k`；
- 兜底规则序时，按相似度取前 `min(top_k, 池大小)` 条（保证合法、满额）；
- 若后续确认官方要求“必须满 top_k”，把兜底逻辑复用到“模型给少了”的分支即可（加一个 `pad_to_top_k` 开关，默认关）。

## 7. 评测方案

### 7.1 代理真值（stage1 无官方答案）

| 信号 | 来源 | 用途 | 局限 |
|---|---|---|---|
| 日期批次先验 | 200 天 × 10 条；40 个日期题 | `date-batch recall@10` | 批次内可能有明显冲突项 |
| 独立规则解 | `artifacts/consensus_answers/subs/task2/answer.jsonl` | 池召回、Jaccard、nDCG | 另一套规则解，不是官方答案 |
| M3 / M7 | 现有产物 | 对照 | 同质化，不能当金标 |
| 人工盲测 | 20 题分层抽样 | 判断模型序是否真的更好 | 成本高、主观 |

### 7.2 指标（按日期/非日期分桶）

| 类别 | 指标 |
|---|---|
| 功能 | 合法提交 50/50、官方校验通过、模型 strict JSON 率、fallback 数 |
| 召回 | 池大小、日期题当日批次入池数/10、date-batch recall@10、代理池召回（分桶） |
| 最终结果 | 代理 Jaccard@k、nDCG@k、`below_top_k` 比例 |
| 价值 | 模型结果 vs 规则序的 Jaccard / 净胜率（人工盲测） |
| 成本 | 平均延迟、输入/输出 token、显存 |

### 7.3 消融

| 实验 | 变量 | 目的 |
|---|---|---|
| E1 | `same_date_credit` ∈ {0, 0.5, 0.8, 1.0} | 日期信用到底带来多少 recall / 多少噪声 |
| E2 | `multiplier` ∈ {2, 3, 4}（日期/非日期可分别） | 2× 是否够；非日期题是否需要放大 |
| E3 | `behavior_events` {开, 关} | 3.3 的事件级行为特征是否解决并列类 |
| E4 | 卡片证据 {精简, 完整} | `dAlt/dSpd/turn/circ` 是否值得 token |
| E5 | 模型 {Qwen3-1.7B, 4B} | 4B 是否必要 |
| E6 | 规则序 vs 模型结果 | **核心：模型到底有没有增益** |
| E7 | 官方结构直接输出 vs picks 中间格式（历史对照） | 直接输出的 ID 错误率/重试率（本版必须验证） |

### 7.4 验收门槛

| 门槛 | 标准 | 不达标怎么办 |
|---|---|---|
| G1 功能 | 50/50 合法；strict JSON ≥ 99%；fallback 0 | 修 prompt/校验/兜底 |
| G2 日期题召回 | 当日批次入池均值 ≥ 9/10；date-batch recall@10 ≥ 0.9；代理池召回 ≥ 0.8 | 调日期信用/权重 |
| G3 行为主导题召回 | 代理池召回 ≥ 0.5（3.3 事件级行为特征后） | 放大池到 3–4×；仍不行说明事件特征还不够细 |
| G4 最终结果 | 模型结果代理 Jaccard/nDCG 不低于规则序；人工盲测 ≥ 60% 题更好 | 退化为“模型只选集合、规则序排序”；再不行只保留规则序 |
| G5 成本 | ≤ 8 s/样本（4090）、≤ 10 GB 显存、1 次调用/样本 | 减池/卡片/输出 |

> G3 是本版最关键的新增门槛：2×池对非日期题只有 0.158 代理召回，不先修相似度就接模型，等于让模型在并列类里抽签。

## 8. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 2×池在纯行为题上被并列类淹没 | 模型看到随机一小撮 | 3.3 事件级行为检测；调阈值/放大池只能缓解不能解决；G3 门槛 |
| 2 | 日期信用把明显冲突项带进池 | precision 下降 | 模型按 `fail/db/spd` 过滤；`same_date_credit` 可调 0 |
| 3 | 官方真值只认严格时间窗 | 日期信用引入噪声 | E1 消融；保留 credit=0 版本 |
| 4 | 模型直接输出编号时抄错/编造 | 校验失败、重试/回退 | 闭集校验 + 1 次重试 + 规则序兜底；report 统计 ID 错误率 |
| 5 | 模型给的结果少于 top_k | 若指标要求满额会扣分 | prompt 要求尽量满；`pad_to_top_k` 开关备用 |
| 6 | 模型只是复述规则序 | 无增益 | E6 + 人工盲测；无增益就退化为集合选择/规则序 |
| 7 | 长 prompt 下 JSON 违规 | fallback 上升 | 512 tokens、卡片精简、strict + 错误回喂 |
| 8 | 复赛模型约束 | 不合规 | 只用 1 个本地 Qwen3-4B，不引入 BGE/reranker |
| 9 | 无官方答案 | 无法证明提升 | 三重代理 + 人工抽检，明确“相对评测” |
| 10 | 可复现性 | 结果漂移 | 贪心、固定 prompt 版本、缓存池、run manifest 哈希 |

## 附录 D：指标定义

- **代理池召回**：`len(池 ∩ 代理真值 top_k) / top_k`，模型可达到的理论上限。
- **date-batch recall@10**：日期题最终前 10 中属于“查询日期当天 10 条”的比例。
- **Jaccard@k**：`len(预测 ∩ 代理真值 top_k) / len(预测 ∪ 代理真值 top_k)`。
- **nDCG@k**：以代理真值排名为相关性，按预测顺序折损累计。
- **below_top_k**：模型输出条数小于 top_k 的样本占比。
- **ID 错误率**：模型输出中不在池内/重复/编号抄错的样本占比（校验拦截时统计）。
- **净胜率**：人工/代理判定“模型结果优于规则序”的题数占比（平局不计）。
